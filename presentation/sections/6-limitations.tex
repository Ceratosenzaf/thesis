\section{Limitations}\label{sec:limitations}

\begin{frame}{\secname}
	\framesubtitle{Some Shortcomings}

	The usage of macros makes the tool flexible and powerful, but it also introduces some limitations and shortcomings, e.g.:

	\begin{tabular}{p{0.45\textwidth} p{0.55\textwidth}}
		\begin{itemize}
			\item Boilerplate % additional annotations are required (especially in the spec! macro) to guide the monomorphization process, but if this was implemented natively in the compiler, this would not be necessary
			\item Compile-Time Overhead % The use of macros and build scripts can introduce some compile-time overhead, especially in large codebases with many specialized implementations
			\item Language Features Support % some language features are not fully supported yet (e.g. existential types or mutable references)
		\end{itemize}
		 &
		\begin{itemize}
			\item Same Project Traits % only supports specialization for traits defined within the same crate, limiting its usability with external libraries
			\item Warnings and Errors % error messages generated by the macros can be less informative than native compiler errors, making debugging more challenging
			\item Trait Bounds % Since the tool generates a monomorphic version of each trait involved, the ability to involve those traits in trait bounds elsewhere in the code is lost
		\end{itemize}
	\end{tabular}

\end{frame}
